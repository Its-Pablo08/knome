  • Roles: the four roles in code are Employee, Community Admin, HR Administrator, System Administrator. There is no separate “Lead” role.

1. Executive Summary & Architecture Overview

1.1 What is Knome?

Knome is MPOnline Limited’s internal enterprise social network and knowledge portal. It combines professional networking (similar to LinkedIn), long-form knowledge sharing (similar to Medium), short and long video (similar to YouTube) and peer recognition into one secure internal website.

1.2 Goals

  • Connect people across departments through profiles, follows and mutual connections.
  • Share knowledge through posts, articles, wikis, videos, podcasts and short clips.
  • Communicate privately with end-to-end-style encrypted one-to-one chat — restricted to connected colleagues only.
  • Organise teams in public and private communities with admin-approved membership.
  • Recognise contribution with Karma points, tiers and a leaderboard.
  • Broadcast corporate announcements and govern the platform through an Admin Console, audit trail and feature switches.

1.3 High-level architecture

Browsers talk to the ASP.NET Core API over REST (JSON + JWT bearer token) and keep a WebSocket open to the SignalR hub for live notifications, chat and presence. All business rules live in the API; data is stored in SQL Server and uploaded files in the API’s wwwroot folder.

5. Module-by-Module Walkthrough

Each module has a blue panel (what a user experiences) and a grey panel (how it is built).

5.1 Authentication, Roles & Account Status

What users see
  • Sign in with Employee ID (or e-mail) and password.
  • First sign-in creates a pending role request and sends a welcome e-mail.
  • Suspended or inactive accounts are refused with a clear message.
  • Admins see an Admin Console tab for role requests.
How it works
  • AuthService.LoginAsync looks the user up, auto-syncing from EmployeeHub if unknown.
  • Password checked against the local BCrypt hash, falling back to the MPO OIDC token endpoint.
  • A JWT carrying the role claims is issued (default 480 min). /api/auth/me returns the current user.
  • [Authorize(Roles = …)] attributes enforce RBAC.

5.2 Newsfeed & Posts

What users see
  • A dashboard feed mixing posts, articles, videos and podcasts, with a “hot” ranking view.
  • Quick posts (up to 400 characters) with images, documents and @mentions; images appear as a grid.
  • Schedule a post to publish later; saved drafts.
  • Text is screened against the restricted-keyword list before publishing.
How it works
  • /api/posts (CRUD, “my”, per-user) and /api/feed (home, hot, dashboard).
  • Post fields include AudienceType, Status, ScheduledDate, PublishedDate; attachments in PostAttachments.
  • ScheduledPostHostedService publishes due posts and notifies followers.
  • Hot score ≈ (Reactions + Comments×2 + Shares×3) ÷ time-decay, cached in HotPostsScoreCache.
  • Mentions create Mention notifications.

5.3 Social Engagement

What users see
  • React to posts with Like, Celebrate, Support or Heart.
  • Comment, reply to comments (nested), edit and delete own comments.
  • Bookmark content to a “Saved” page; share inside Knome; report inappropriate content.
How it works
  • /api/interactions/{contentType}/{contentId}/… — one generic API for posts, articles, videos, podcasts, wikis and clips: comments, react, reactions, share, bookmark, report, summary.
  • Reports land in a moderation queue (reports, reports/pending, reports/{id}/resolve).
  • Every action publishes a notification and may award Karma.

5.4 Enterprise Communities

What users see
  • Browse public and private communities by category; request to join private ones.
  • Community feed, member list, rules and FAQ, and a shared files library.
  • Admins approve or reject join requests, add/remove members, promote admins and pin posts.
How it works
  • Community (type, ApprovalStatus, rules, FAQ) and CommunityMember (MemberType, Status, decision audit fields).
  • Endpoints: join, leave, members, members/{id}/decide, admins/{id}, posts, posts/{id}/pin, files.
  • Safeguards: a community cannot lose its last admin; at most three pinned posts.
  • Each decision notifies the user (CommunityJoin, CommunityInvite).

5.5 Direct Messaging (connection-gated & encrypted)

What users see
  • One-to-one chat with live delivery, typing indicators, online status and read receipts.
  • Attachments, emoji picker, replies, edit, delete-for-me / delete-for-everyone, and six emoji reactions (👍 ❤️ 😂 😮 😢 🎉).
  • Only connected colleagues can chat. For anyone else the message box is replaced by a lock banner with a Connect button (or “Request Pending”).
  • The “Message” button on profiles and community members appears only for connected people.
How it works
  • /api/messages: users, conversations, history/{id}, send, {id} (edit/delete), {id}/reactions, read/{id}, online-users.
  • SendMessageAsync enforces the rule server-side via AreUsersConnectedAsync (accepted request or mutual follow).
  • Message text is encrypted with AES-256-GCM before it is stored in UserMessages.
  • Delivery uses SignalR groups named User_{id}; an administrator can disable messaging globally.

5.6 Network & Connections

What users see
  • Discover colleagues with mutual-connection counts and common communities.
  • Follow (one-way, to see someone’s content) or Connect (two-way relationship that unlocks chat).
  • Send, accept, reject, cancel and remove connections; see pending requests.
How it works
  • ConnectionRequests (Pending → Connected) plus two Followers rows are created on accept.
  • Endpoints: POST /users/{id}/connect, DELETE …/connect/cancel, POST /users/connect/accept|reject/{requestId}, DELETE …/connect, GET /users/connections/requests, GET /users/{id}/connections.
  • If both sides invite each other, the requests auto-merge into a connection.

5.7 Knowledge: Wikis & Articles

What users see
  • Articles: rich-text blog posts with tags, attachments, read-time and view counts.
  • Wikis: structured knowledge pages made of reorderable sections, with collaborators and sharing.
  • Version history with the option to restore an older version; archive and restore wikis.
How it works
  • /api/articles with ArticleVersions snapshots; /api/wikis with WikiSections, WikiCollaborators, WikiShares, WikiTags, WikiVersions.
  • Wiki endpoints include sections, sections/reorder, collaborators, shares, versions/{id}/restore, activities, archive, restore.
  • Sharing and collaboration produce Share / Community (wiki) notifications.

5.8 Media Hub: Clips, Videos & Podcasts

What users see
  • Clips: short vertical videos with reactions, bookmarks, shares and viewer analytics.
  • Videos: upload (up to 500 MB) or embed; tags; playlists support.
  • Podcasts: audio series and episodes (up to 100 MB) with an audio player.
How it works
  • /api/clips, /api/videos, /api/podcasts, plus /api/media for uploads (magic-byte file validation).
  • Clips expose viewers, engagement, and admin moderation (admin/all, admin/{id}/status).
  • Limits come from MediaConstants; feature switches can disable each module.

5.9 Karma & Gamification

What users see
  • Points for contributing and engaging; a tier badge and progress bar on the profile.
  • Karma history page and a company leaderboard.
How it works
  • KarmaService writes KarmaTransaction rows and updates KarmaBalance (TotalPoints, BadgeLevel); balances never go below zero.
  • Daily caps prevent farming; /api/karma: my, user/{id}, leaderboard, award.

5.10 Notification Center

What users see
  • A bell with an unread count; a list with All / Unread filters, mark-all-read and delete.
  • A pop-up toast and a soft chime when something happens in real time.
  • Clicking an alert opens the exact item (post, profile, community, wiki, connection requests …).
  • A settings dialog to turn categories on or off (comments, reactions, followers, invites, mentions, community posts, jobs).
How it works
  • Any service calls INotificationService.PublishAsync(...); PublishBroadcastAsync handles HR announcements.
  • Preferences are checked first, the row is saved in Notifications, the DTO is enriched (title, sender, TargetUrl) and pushed with ReceiveNotification to group User_{id}.
  • Event types: Comment, Reaction, Mention, Follower, ConnectionRequest, Community, CommunityJoin, CommunityInvite, Share, Job, Badge, Wiki, HRAnnouncement.

5.11 Admin Console & Governance

What users see (admins)
  • Switches to turn modules on or off: messaging, e-mail, posts, articles, clips, wiki, videos, podcasts.
  • Restricted-keyword list, moderation report queue, user suspension, role-request approvals, HR broadcast composer and analytics.
How it works
  • /api/settings + SystemSetting entity, read by the frontend through systemConfig.js; controllers also check flags (e.g. messaging).
  • /api/interactions/restricted-keywords, /api/audit (immutable AuditLog, System Admin only), /api/analytics.
  • Suspensions use IsPermanentlySuspended / SuspendedUntil and are enforced at login and by a suspension guard.

5.12 Search, Jobs & Abbreviations

  • Global search (/api/search) spans people, communities, posts, articles, videos, podcasts and jobs, with search history.
  • Jobs board (/api/jobs) — HR/System Admin publish internal vacancies; JobExpiryHostedService closes expired postings automatically.
  • Abbreviations (/api/abbreviations) — a shared company glossary.
  • Data archival — DataArchivalHostedService plus ARCHIVE_*.ps1 scripts keep logs and uploads from growing without limit.

7. Security, Privacy & Encryption

7.1 Authentication & authorization

  • JWT Bearer (HS256). The signing secret comes from configuration or the KNOME_JWT_SECRET environment variable and must be at least 32 characters. Default lifetime is 480 minutes (JwtSettings.ExpiryMinutes). The API also accepts MPO-issued tokens through a second authentication scheme.
  • Passwords are stored as BCrypt hashes (UserCredentials.PasswordHash).
  • RBAC. Four roles are defined in Constants/Roles.cs; endpoints use [Authorize(Roles = …)] and named policies.
  • Brute-force protection. LoginRateLimiter allows 30 login requests per minute per client IP, then returns HTTP 429.
  • Suspension. Suspended or inactive users cannot sign in; suspension guards protect write operations.

7.2 Direct-message encryption (AES-256-GCM)

Message bodies are never stored as plain text. MessageEncryptionService encrypts each message with AES-256 in Galois/Counter Mode, which provides both confidentiality and tamper detection.

Important to understandEncryption is applied by the server (encryption at rest). It protects the database contents, but it is not client-side end-to-end encryption — the API can decrypt messages. Keep the message keys in environment variables or a secrets manager, never in source control.

7.3 Connection-gating logic

Two users may exchange direct messages only when AreUsersConnectedAsync(a, b) returns true:

public async Task<bool> AreUsersConnectedAsync(int userId1, int userId2)
{
    // 1) An accepted / connected ConnectionRequest in either direction
    // 2) OR a MUTUAL follow: user1 follows user2 AND user2 follows user1
    // A one-way follow is NOT enough.
}
  • Server enforcement: SendMessageAsync throws BadRequestException("You can only message colleagues you are connected with.") when the check fails — a custom client cannot bypass the UI.
  • UI enforcement: Messages.jsx locks the composer, shows a banner and offers Connect; Profile and Community pages show the Message button only to connected users.
  • Conversation list & search expose an IsConnected flag so badges (“Connected” / “Not Connected”) are accurate.

7.5 Known risks to review before production

Findings from the code review — recommended hardening
  • Development login shortcuts. AuthService.LoginAsync accepts the literal passwords Password@123 and SSO_BYPASS for any account, creates a default credential if one is missing, and contains hard-coded employee-ID special cases. Remove these before any production or shared deployment.
  • Credentials in scripts. START_KNOME.ps1 embeds a SQL login and server names. Move them to environment variables or user secrets.
  • SignalR hub trust. NotificationHub.JoinUserGroup only rejects a mismatch when the connection carries a user id, and SendDirectMessage relays a client-supplied payload to the recipient group without the connection check. Verify the hub requires authentication and consider applying the same connectivity rule there.
  • Server-side encryption keys. Ensure production keys are supplied through environment variables and rotated via KeyVersion.

Step 2 — Create and prepare the database

  2. Run the helper scripts for feature tables (the launcher also runs them automatically): SETUP_WIKI_DB.ps1, SETUP_CLIPS_DB.ps1, SETUP_MESSAGES_DB.ps1 (or CreateUserMessages.sql in SSMS).

Edit Backend/Knome.API/appsettings.Development.json (never commit real secrets) or use environment variables / user-secrets.

{
  "ConnectionStrings": { "DefaultConnection": "Server=YOUR_SERVER;Database=Knome;User Id=YOUR_USER;Password=YOUR_PASSWORD;TrustServerCertificate=True" },
  "Jwt": { "ExpiryMinutes": 480 },
  "MessageEncryption": { "DefaultKeyVersion": 1 }
}
# Environment variables (recommended for secrets)
KNOME_JWT_SECRET        = <random string, 32+ characters>
KNOME_MESSAGE_KEY_V1    = <base64 of 32 random bytes>
TipGenerate a message key in PowerShell: [Convert]::ToBase64String((1..32 | % { Get-Random -Max 256 }) -as [byte[]]). Check the exact configuration key names in appsettings.json for your branch.

Step 4 — Run the backend

Step 6 — One-click alternative

From the repository root run .\START_KNOME.bat. The launcher frees ports 5095/5096/5173, runs npm install on first use, verifies the database, ensures wiki/clips/messages tables exist, starts the API and the UI, and (if IIS is configured) starts the Knome and EmployeeHub sites on 8080/8081. Press Ctrl+C to stop everything.

  1. Create a feature branch; keep controllers thin and put rules in services.

Frequently asked questions

What is the difference between Follow and Connect? Follow is one-way (you see their content). Connect needs the other person’s acceptance and creates a two-way relationship — only that unlocks private chat.

Can administrators read private messages? Messages are encrypted at rest in the database, but the API decrypts them for participants. Treat access to the server and keys as sensitive.

Where do new roles come from? Everyone starts as Employee. A role request is created at first sign-in; HR or System Administrators approve elevated roles in the Admin Console.

How do I add a new notification type? Add a constant in NotificationTypes, call PublishAsync from the relevant service, and (optionally) add a title/target mapping in NotificationService.EnrichNotificationDtoAsync.
